# Applying the report

Loaded at Phase 6. Defines the dangling-reference check, the mutation order, `index.md` generation, the `log.md` entry schema, and the commit.

## Dangling-reference check (before any mutation)

For every approved row, each RowID listed in its `Depends on` must also be in the approved set. If any dependency is unapproved or rejected:

- Block. Make no mutation.
- List the dangling rows: `<RowID> depends on <RowID> which is not approved`.
- Return to approval so the user resolves it (approve the dependency, or reject the dependent row).

Only proceed when the approved set is closed under `Depends on`.

## Mutation order

Apply in this order so the wiki is never left internally inconsistent mid-write:

1. **Page creations and modifications.** Write or edit pages per `.claude/rules/page-schema.md`: front-matter (set `created` on new pages, bump `updated` on all touched pages, merge `sources[]`), section-level `*Sources:*` lines, claim-level footnotes, supersede annotations for Table 3 rows. Use the conflict action decided per row.
2. **Link updates (Table 4).** Add, update, or remove the `[[wiki-link]]`s.
3. **Regenerate `index.md`** from page front-matter (see below).
4. **Append the `log.md` entry** (see below), incorporating any user edits from the preview.

## index.md generation

`index.md` is a derived projection. Regenerate it wholesale by scanning the front-matter of every page under `./wiki/` (excluding `index.md`, `log.md`, `overview.md`). Never hand-edit it; never carry a version block on it.

Shape:

```markdown
# Wiki index

> Generated by /ingesting-sources at each Apply. Derived from page front-matter. Do not hand-edit.

## <tag>

| Page | Type | Description | Created | Updated |
|---|---|---|---|---|
| [[<slug>]] | <type> | <description> | <created> | <updated> |
```

- One `##` group per tag, tags in alphabetical order. Within a group, pages alphabetical by slug.
- A page with N tags appears in N groups. A page with no tags goes under a final `## untagged` group.
- `Description` is the front-matter `description` verbatim. `aliases` are not surfaced here.

Worked fragment (one page carrying tags `auto-industry` and `ev`):

```markdown
## auto-industry

| Page | Type | Description | Created | Updated |
|---|---|---|---|---|
| [[tesla-inc]] | entity | American electric vehicle and clean energy company, founded 2003. | 2026-05-21 | 2026-05-31 |

## ev

| Page | Type | Description | Created | Updated |
|---|---|---|---|---|
| [[tesla-inc]] | entity | American electric vehicle and clean energy company, founded 2003. | 2026-05-21 | 2026-05-31 |
```

## log.md entry schema

`log.md` is the chronological activity record, written only by this skill. Append the new entry at the end (oldest-first). No version block. First ever entry is preceded by the header `# Wiki log` if the file does not yet exist.

Entry shape:

```markdown
## <YYYY-MM-DD> — <mode>: <source_title>
- Source: [[<source_file>]] "<source_title>" (issued <issued_date>)
- Mode: ingest | re-ingest
- Pages created: [[<slug>]], ...        (or: none)
- Pages modified: [[<slug>]], ...       (or: none)
- Rows applied: <a> modifications, <b> creations, <c> conflicts (<breakdown by action>), <d> link updates
- Notes: <free text; carries user edits from the preview, or "none">
```

Use the current date for `<YYYY-MM-DD>`.

Worked entry (matching the report example in `report-and-approval.md`):

```markdown
## 2026-05-31 — ingest: Tesla Q1 2026 Earnings Report
- Source: [[q1-earnings.pdf]] "Tesla Q1 2026 Earnings Report" (issued 2026-04-10)
- Mode: ingest
- Pages created: [[dojo-supercomputer]]
- Pages modified: [[tesla-inc]]
- Rows applied: 2 modifications, 1 creation, 2 conflicts (1 supersede, 1 do not add), 1 link update
- Notes: none
```

## Commit

One atomic commit per applied report. Stage only the wiki write surface (`./wiki/`), never `./raw/`.

```
git add ./wiki
git commit -m "<subject>" -m "<body>"
```

- **Subject** (auto-generated, concise): `ingest(<source-stem>): <a> mod, <b> new, <c> conflict` — use `reingest(<source-stem>): ...` in re-ingest mode. Keep under ~72 characters. Concrete instance: `ingest(q1-earnings): 2 mod, 1 new, 2 conflict`.
- **Body:** the exact `log.md` entry applied.

After the commit succeeds, release the wiki lock and confirm: `✓ Committed <subject>; lock released`. If the commit fails, the lock stays held; report the git error and let the user retry or Cancel.
