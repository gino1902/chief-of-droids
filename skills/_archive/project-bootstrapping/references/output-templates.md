# Output Templates

Templates for the three artefacts generated by the `project-bootstrapping` skill.
Substitute all `[PLACEHOLDER]` values from interview answers before rendering.
Scan output for any remaining `[PLACEHOLDER]` strings — flag any that could not
be filled and ask the user before proceeding.

Generation order: FRAMING.md (scaffold) → CLAUDE.md → system prompt.
Each file is confirmed and written before the next is generated.

## Template 2 — CLAUDE.md

*Repo output defaults. References FRAMING.md as the binding scope definition.*

```markdown
# CLAUDE.md — [PROJECT_NAME]

> Output defaults for the `[REPO_NAME]` repo.
> Applies to all outputs unless overridden by a `CONSTITUTION.md`.

---

## Repo Purpose

[SOLUTION]
Domain: [DOMAIN]

---

## FRAMING.md Alignment

FRAMING.md is the binding scope definition for this project.
On session start: read `FRAMING.md` from the repo root via Filesystem tool.
Every output must be traceable to an objective or constraint in FRAMING.md.
If a request cannot be traced to FRAMING.md, flag it before proceeding:
`⚠️ Out of scope — not traceable to FRAMING.md objectives or constraints`
Never modify FRAMING.md — it is user-owned.

---

## Format

- Default output format: [FORMAT_DEFAULTS]
- Use plain prose with tables and code blocks where appropriate
- No decorative formatting: no emoji, no horizontal rules as decoration
- Use headers sparingly — one level of nesting is usually enough
- Prefer tables over bullet lists for structured comparisons
- All code examples use fenced blocks with language tag

---

## Tone

[TONE]
- No preamble summarising what you are about to do — act directly
- Flag uncertainty explicitly: `> ⚠️ Unverified — check against official docs`
- Flag outdated content: `> ⚠️ Stale — verify before use`
- Flag scaffolded content: `> 🔲 To be defined — awaiting user input`

---

## Minimum-Necessary Rules

[MINIMUM_NECESSARY]

---

## Gotchas

[GOTCHAS — if empty, insert: > 🔲 To be defined — add known failure modes as they emerge]

---

## Version Block

Every `.md` file written to disk must include a version block at the bottom:

| Field        | Value                  |
|:-------------|:-----------------------|
| Version      | 1.x                    |
| Last Updated | YYYY-MM-DD             |
| Status       | Draft / Review / Final |

---

## Flagging Rules

- Unverified claims: `> ⚠️ Unverified — check against official docs`
- Decisions made in session: `> [DECISION] [date]: [what and why]`
- Assumptions: `[ASSUMPTION]`

---

| Field        | Value      |
```
