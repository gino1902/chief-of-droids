# QA Checklist

Run against any FRAMING.md — during `build framing` (pre-proposal) and
`challenge framing` (post-read critique).

---

## Problem framing

- [ ] Problem statement is specific — not a generic pain point
- [ ] Root cause is stated or hypothesised — not just symptoms
- [ ] Status quo cost is quantified or estimated — not just described

## Stakeholder clarity

- [ ] Primary stakeholder (decision-maker) is named or typed
- [ ] Secondary stakeholders (impacted, consulted) are identified

## Value articulation

- [ ] Expected value is measurable — KPI, metric, or threshold named
- [ ] Time-to-value is estimated — not open-ended
- [ ] Value is linked to a stakeholder need — not a technology capability

## Scope discipline

- [ ] Scope boundary is explicit — what is out of scope is stated
- [ ] No scope creep signals (multiple unrelated problems framed as one)
- [ ] Constraints (budget, timeline, org, technical) are listed

## Assumptions and risks

- [ ] Key assumptions are named — not buried in narrative
- [ ] At least one risk or dependency is identified
- [ ] No unsupported superlatives ("best", "most efficient", "only solution")
