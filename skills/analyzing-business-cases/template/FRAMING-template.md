# FRAMING.md — use-case-<id>

## Context
Describe the stable state: the business environment, organizational structure, key processes,
and value streams relevant to this use case. Write as if everything is functioning — this is
the "as-is" landscape, not the diagnosis. No problem statement here.

## Problem
Describe the delta: what is broken, missing, or suboptimal within the context above, and why
it matters. Only include what would not be true if things were working correctly.

## Client
Who the solution is for. Include primary audience (decision-maker or end user) and any
secondary stakeholders. Note whether the audience is technical, business, or mixed.

## Objectives
Business value outcomes expected from the solution. State as measurable or observable results,
not activities. One outcome per line.

## Solution
What we intend to build or implement to address the problem. One paragraph maximum.
Approach only — no implementation detail, no feature list.

## Constraints
Limits, conditions, and boundaries the solution must respect. Includes: technical boundaries,
data availability, timeline, budget, or any hard exclusions.
